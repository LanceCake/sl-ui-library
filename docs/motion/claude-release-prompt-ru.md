Статус этого документа: производственный бриф, а не подтверждение публикации. Адрес библиотеки установлен по README и конфигурации Pages: https://sltowl.github.io/sl-ui-library/. ## 1. Доступ к настоящим компонентам

Сначала проверь, какие файлы доступны в твоём рабочем окружении. Ссылка на сайт или установленный плагин сами по себе не дают доступа к компьютеру владельца. Для Claude Code предпочтителен checkout проверенного коммита с новыми пакетами и приложенной картой соответствия. Для Claude с файловым окружением владелец может передать архив исходников релиза и этот бриф; распакуй его в рабочую папку. Поддерживаемый клиент Claude может использовать ZIP плагина через Customize → Plugins, но наличие именно новых вариантов надо проверить по каталогу, а не предположить.

Прочитай `docs/agents.md` и `plugins/sl-ui-library/scripts/integration-guide.md`. Используй `node plugins/sl-ui-library/scripts/library.mjs --help`, затем поддерживаемые CLI команды search/inspect/read/install для реальных вариантов. `inspect` возвращает integration contract. Не назначай ключ эксперимента идентификатором экспортного пакета без сверки: например, `contact` встречается в нескольких группах. Уникальный адрес в этом брифе — сочетание папки, локального key и review number. Запиши реальное соответствие variant → source files в проект фильма.

При отсутствии новых компонентов в старом плагине читай одобренные локальные источники по whitelist; не заменяй их похожими старыми кнопками. Исходные композиции также используют существующие библиотечные примитивы: это допустимо как внутреннее устройство нового элемента, но новый герой кадра должен соответствовать одобренному сценарию. Не делай самовольную установку плагина в личную конфигурацию пользователя.

Сохраняй вместе HTML, scoped CSS, inline SVG, контроллеры состояния, шрифты и ресурсы. Framework-адаптация допустима при сохранении геометрии и поведения. Не заменяй авторские SVG символами Unicode, emoji, иконками из случайного набора или картинками, сгенерированными по описанию. Сохраняй viewBox, path, stroke, группы анимации и пропорции. Где требуется, отрендери исходный DOM в контролируемом браузере или перенеси его в детерминированную композицию с проверкой кадр-в-кадр. Не снимай экран всего каталога и не делай фильм из скриншотов карточек.

## 3. Визуальное направление

Характер: премиальный предметный фильм, строгая типографика, живая геометрия, высокая энергия, точная причинность. Материал — матовый графит, чёрная плоскость, белое поле, тонкие нейтральные границы и мягкая контактная тень. Никаких случайных неоновых градиентов, разноцветного конфетти, стоковых телефонов и декоративной стеклянности поверх каждого контрола.

Возьми существующие поверхности за основу: в account-core реальные переменные используют #303030, #252525, #f4f4f4, #c6c6c6, #505050; карточка имеет скругление 20px, SVG 20×20, stroke 1.6, мягкую неглубокую тень. Светлая сцена может иметь фон #f2f2f2; тёмная — почти чёрный. Это параметры сценографии, не разрешение перекрашивать каждый исходник без проверки. На белом фоне графитовый интерфейс остаётся главным объектом; в чёрном окружении отделяй его гранью и освещением. Граница должна оставаться различимой после H.264 compression.

Внутри контролов сохрани реальную исходную типографику и английские labels релизных пакетов. Русские названия whitelist служат режиссёрской разметкой. Не накладывай перевод поверх текста кнопок и не смешивай локальный русский preview с английским экспортом в одной сцене. Для внешних титров используй короткие английские фразы: “A new way to interact”, “Choose. Refine. Continue.”, “Made for real flows”, “SL UI Library”, “Explore the library”. Не используй обещания скорости бизнеса, роста конверсии, числа пользователей, сертификатов или недоказанные marketing stats. Шрифт титров возьми из доступного лицензированного комплекта проекта; Instrument Sans применяй, только если его файл действительно передан. Для исходников с Segoe UI учитывай доступность шрифта в среде рендера: подмену согласуй как видимую адаптацию и проверь переносы.

Свет и камера нужны для читаемости состояния. Допустимы деликатные 3D наклоны 5–12°, разнос слоёв по глубине, крупные плоские макрокадры и динамичные пролёты между группами. В момент взаимодействия возвращай контрол близко к фронтальному положению. Не превращай буквы и SVG в растянутую резину. Motion blur разрешён на транзитном объекте, но текст результата должен быть резким.

## 4. Формат, ритм и motion system

Основной мастер: 60 секунд, 1920×1080, 60 fps, ровно 3600 кадров. Диапазоны кадров ниже включают обе указанные границы: 0–239 означает 240 кадров, следующая сцена начинается с 240. Монтаж должен иметь намеренные ускорения и остановки: подготовка → действие → видимый результат → перенос энергии в следующую сцену. Не используй одинаковый fade-in для каждой карточки. Не оставляй бесконечного плавания у всех объектов.

За основу внутренних состояний возьми настоящие tokens: content 200ms, layout 300ms, easing cubic-bezier(.22,1,.36,1); daily-controls использует также 50ms stagger и 100ms exit. Everyday buttons основаны на критически затухающей пружине: stiffness 700, mass 1, dampingRatio 1; redo/signout — stiffness 300. Сохрани назначение этих движений и не делай лишнего bounce. Создай отдельный film.tokens файл для камеры, переходов и акцентов; раздели названия ui.*, scene.*, camera.*. На 60 fps 50/100/200/300ms соответствуют 3/6/12/18 кадрам. Переходы сцен могут длиться 24–42 кадра, короткая подготовка 4–8, читаемая фиксация результата 24–48. Это режиссёрские параметры, не заявленные tokens библиотеки.

Иерархия в каждом шоте: одно главное действие; второе движение обслуживает его; фон реагирует позднее и слабее. Stagger 3–5 кадров, направление цепочки совпадает с направлением взгляда. После сильного пространственного перехода дай паузу. Мощность создаётся амплитудой и контрастом темпа, не непрерывной тряской. Внутренние движения должны корректно возвращаться: выбор → изменение → отмена/возврат, без скачка в начальное состояние.

Каждый переход обязан иметь источник в предыдущем кадре и точку приземления в следующем. Разрешены увеличенная плоскость выбранной карточки, движущийся underline, граница splitter, расширившаяся панель accordion, реальная линия signature. Геометрическое сходство может связать два объекта, но не должно менять смысл существующего control или выдумывать новую промежуточную функцию.

### 00:47–00:54 / кадры 2820–3239 / чёрное поле / «Много деталей — один язык»

Камера проходит через управляемую систему из трёх пространственных слоёв новых компонентов. Не показывай всю таблицу из 91 элемента микроскопическим текстом. ### 00:54–01:00 / кадры 3240–3599 / белое поле / «Открыть библиотеку»

Белая маска раскрывает ровный фронтальный ансамбль 3–5 настоящих новых элементов. В первые две секунды ещё одна общая причинная цепочка: выбор → изменение содержания → спокойная фиксация. Затем объекты расходятся по краям, освобождая центр. Титр “SL UI Library”, ниже “Explore the library”, затем читаемый `sltowl.github.io/sl-ui-library`. Адрес появляется не позже 57-й секунды и остаётся минимум 2.5 секунды. Не рисуй поддельный логотип: используй существующий разрешённый знак/словесный бренд либо аккуратный текст. Завершение с остаточным движением 6–10 кадров и устойчивым финальным hold. Если требуется seamless loop, сделай отдельную loop-версию; не уничтожай читаемость финального URL ради цикла.

## 6. Читаемость, вертикаль, accessibility

Для 1920×1080 оставь минимум 96px безопасного поля; крупные титры примерно 80–130px по композиции, важные labels героя после масштабирования не мельче 24px. Контрол в масштабе должен сохранять толщину штрихов и пропорции, а не менять stroke ради визуального эффекта без проверки. Длинный panel можно скомпоновать через макрокадр содержимого; не обрезай важный шаг подтверждения. В scene 6 не показывай настоящие личные данные.

Опционально подготовь отдельный 1080×1920, 60 fps монтаж той же длительности. Перестрой композицию и направление камеры под вертикаль; не делай center crop горизонтального мастера. Ключевое действие держи в центральной области; оставь ориентировочно 120px по бокам, 220px сверху и 300px снизу для интерфейса платформы. Это рабочая сетка, которую проверяют на целевой площадке. Сократи количество второстепенных карточек, показывай их по очереди. На 390px preview важные подписи должны оставаться читаемыми без увеличения.

Полноэкранные белое/чёрное чередуются по крупным сценам через пространственные переходы, без строба и коротких вспышек. Не делай быстрых многократных инверсий яркости. Если создаёшь интерактивный web preview, добавь pause/play и учитывай prefers-reduced-motion: крупные camera moves, параллакс и пространственные wipe заменяются спокойными cut/crossfade, состояния контролов остаются понятными. Сам MP4 не может автоматически адаптироваться к системной настройке; отдельно экспортируй спокойную версию при доступном времени и ясно её назови. Keyboard/focus исходников не ломай ради съёмки.

## 7. Производство и честность результата

Используй доступный инструмент рендера, подходящий для программной анимации. Если выбран Remotion или аналог, все движения должны быть функцией кадра, без зависимости от Date.now, реального setTimeout, случайных fetch или незафиксированного Math.random. Ключевые состояния реальных контроллеров сначала воспроизведи в baseline и перенеси в timeline без выдумывания результата. Отдельно фиксируй UI state и presentation transform. При анимации DOM на кадрах нужна управляемая clock и ожидание локальной загрузки шрифтов; screenshot до font-ready не годится.

Не делай реальные звонки, платежи, рассылки, удаления, передачи организации, смены пароля или выгрузки данных. Изображай взаимодействие с локальными демонстрационными данными. Сам фильм должен выглядеть как продуктовая демонстрация, а README рендера должен прямо назвать локальный характер сценариев. Не добавляй фальшивые “Payment successful”, “Email sent” или “Account secured”, если исходный контракт этого не подтверждает. Название “91 new approved elements” допустимо только после сверки whitelist и релиза; даже тогда это число элементов, не установок или пользователей.

Аудио опционально. Сделай прежде всего сильный беззвучный монтаж. Если доступен разрешённый оригинальный или лицензированный sound design, привяжи лёгкий клик, мягкое скольжение и низкий impact к конкретным событиям, без постоянного whoosh на каждый объект. Сохрани источник и лицензию. Не скачивай популярный трек и не копируй аудио/анимацию чужого ролика. Если прав нет, экспортируй silent master и отдельно cue sheet для будущего sound designer.

Не публикуй сайт или фильм и не меняй репозиторий/права доступа без запроса владельца. Для этого задания достаточно локальных выходных файлов и review preview.

## 8. Проверка до передачи

Подготовь contact sheet с кадрами в начале, на пике действия и после фиксации каждого раздела, плюс отдельные кадры непосредственно перед и после каждой смены белого/чёрного. Просмотри полностью отрендеренный MP4, а не только исходный timeline. Проверь 3600 кадров, 60 fps, размер 1920×1080, отсутствие чёрных пропусков, потерянных шрифтов, скачков масок, клиппинга текста, недогруженных SVG и неожиданных переносов. Проверь декодирование экспортного файла, а также тихие паузы: компрессия не должна съедать тонкие линии.

Сверь несколько hero кадров с standalone исходником на той же геометрии. После framework адаптации сериализуй только component subtree и используй `library.mjs audit <variant> <rendered-html-file>`, где variant действительно существует в каталоге. Прочитай status: код завершения команды сам по себе не означает source fidelity. `source-markers-present` не заменяет визуальную проверку CSS, SVG и интеракций. Для локальных композиций вне каталога сравни actual DOM/CSS/SVG вручную и запиши ограничение, не выдумывай variant.

Пройди source map и убедись, что ни один отклонённый ID не попал в сцену. Отдельно проверь reversing interactions: accordion open/close, reorder forward/back, poll vote/undo, request cancel. Для интерактивного preview проверь keyboard focus и reduced-motion. Для вертикали проверь кадры в уменьшении до реального размера телефона, не только полноэкранно на мониторе. Пересмотри все маркетинговые фразы: только проверяемые свойства и точный адрес библиотеки.

## 9. Что передать

Передай основной `sl-ui-new-interactions-60s-1080p60.mp4` (H.264, совместимый pixel format yuv420p; bitrate/CRF подбери по визуальному контролю), локальный исходный проект со всеми нужными разрешёнными assets и lockfile, poster PNG, contact sheet, `scene-source-map` (timecode → review number → manifest path → public variant/source files), `render-notes` с командами запуска и честным списком проверенного, optional portrait MP4 и optional calm MP4. Если инструмент позволяет и нужен монтажный запас, приложи качественный промежуточный master отдельно.

Если среда не способна рендерить видео, доведи до максимально полного воспроизводимого проекта, приложи проверенные кадры и точную команду рендера. Прямо скажи, что MP4 не отрендерен; не выдавай HTML preview или storyboards за готовый фильм. Не заканчивай только планом, если доступные инструменты позволяют собрать и проверить результат.

Критерий качества: зритель видит настоящее, разнообразное взаимодействие SL UI Library; следит за одной ясной цепочкой действий; ощущает энергию через масштаб, ритм и причинные переходы; читает состояния; запоминает финальный адрес. Любой эффект должен помогать этой задаче.
